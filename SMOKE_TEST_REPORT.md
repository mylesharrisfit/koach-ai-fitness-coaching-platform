## Prioritized bug list

### P0 — security / data leak / blocks the core loop
1. **Client invites cannot work end to end.** Two independent blockers:
   - Resend is in sandbox (`onboarding@resend.dev`, no verified domain) → only `mylesharrisfitbusiness@gmail.com` can receive any email: invites, reminders, digests, welcome emails, check-in notifications. `_shared/resendEmail.js:25-26`.
   - `validateInviteToken` returns 500 for every live token (suspected missing `SUPABASE_JWT_SECRET`); the setup page then shows "invalid invite". `validateInviteToken/index.ts:55-60`, `ClientSetup.jsx:61-66`.
   - `sendClientInvite` hides both by returning `{success:true}` (`index.ts:101-113`).
2. **Coach dashboard `/` white-screens** (blank page, no error boundary) for coach A and B after login. Console: `TypeError: Cannot read properties of null (reading 'charCodeAt')`. Cause: `getAvatarColor(name = '')` in `components/dashboard/RunMyDayCenter.jsx:47-50` and `TodaySchedule.jsx:30-32`; a default parameter does not guard `null`, and rows with `client_name = NULL` exist for every coach — including messages created by the platform's own automation executor (`_shared/automationActions.js:92` calls `sendMessage` without `client_name`) and by raw API inserts. Other unguarded `name.charCodeAt` sites: `ClientRow.jsx:63`, `ClientListSidebar.jsx:25`, `BroadcastModal.jsx:34`, `ClientInfoSidebar.jsx:19`.
   *No cross-tenant data leak was found anywhere in this run.*

### P1 — feature broken / paywall or integrity bypass
3. **Tier gating is UI-only for AI features.** A Starter coach (and any portal client login) gets 200 from Pro/Elite AI functions (`claudeAssistant`, `aiBusinessInsights`, `aiMessageAssistant`, `aiNutritionInsights`, `aiProgressInsights`, `aiCheckInInsights`, `aiInBodyScan`, `generateSmartMeals`, `generateExerciseLibrary`). `claudeAssistant`, `aiMessageAssistant`, `generateExerciseLibrary`, `mapImportColumns` also **skip the monthly AI quota** entirely (`_shared/aiMetering.js` is not called) → unmetered Anthropic spend, reachable by any signed-in user including portal clients.
4. **Client cap not enforced server-side** (12 inserts accepted on Starter=10). Add-client UI is hidden for everyone (`Clients.jsx:311`), so the only paths are CSV import and invites — neither verified against the cap.
5. **Seven routes lack `PageGuard`** (`/analytics /coaching-templates /automations /ai-insights /team /revenue /at-risk`); `/white-label` is a soft gate.
6. **Any signed-in user (including a portal client) can act as a coach on their own account:** insert clients, programs, teams, automation rules; call `seedTeam`, `initializeReferralProgram`, AI functions. Not cross-tenant, but there is no client/coach role separation; the client's notifications fill with coach-style events ("New client: client-made-client…").
7. **Clients can forge coach identity:** insert messages with `sender='coach'` and `created_by=<coach id>`; set `review_status='reviewed'`, `coach_responded=true`, `coach_notes` on their own check-in via `check_ins_portal_view`. The forged coach message renders as the coach's in the portal.
8. **`submitOnboardingIntake` is an unauthenticated write + email relay:** anyone can file a row into any coach's account by `coachId` and trigger an email to any address, with no rate limit.
9. **Email failures are silent.** `sendClientInvite`, `sendCheckInReminders` (marks reminder sent), `weeklyDigest` (counts sent) all ignore the mailer result.
10. **`weeklyDigest` is not idempotent** (second run sent again).
11. **Push notifications have no send side** (only key + subscription storage).
12. **Supplements display bug (known):** coach Meal Plan tab shows none; portal `normalizeSupplements` drops items whose timing isn't Morning/Night; portal ignores `plan.meals`; portal meal log hides food logs with null `meal_name`.
